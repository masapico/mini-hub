保存方式と特徴

minihubの永続化は組み込みSQLiteを使用します。外部DBサーバーは不要です。

  • 保存先: データディレクトリ内の minuhub.db
  • 特徴: 永続索引から履歴を取得し、履歴全体をGoのメモリへ読み込みません。WALモードで動作するためローカルディスク上に配置します。
  • 排他制御: データディレクトリ内の .minihub.lock によりプロセス単位で排他制御を行います。
  • マーカー: 初回起動時に storage.json が生成され、SQLiteデータベースの整合性を保護します。

server.dataDir の相対パスは設定ファイルのあるディレクトリが基準です。CLIで -data を明示した場合はその値が優先されます。

バックアップと復元

バックアップ

サービス停止後にデータディレクトリ全体をコピーします。DB本体（minuhub.db）だけをコピーせず、storage.json や残存するWALファイル（minuhub.db-wal、minuhub.db-shm）などの関連ファイルも含めてください。設定ファイル（minihub.json）も別途、アクセスを制限して保管します。

  1. サービスを停止し、プロセスの終了を確認します。macOS／Linuxでは前面起動ならCtrl+C、サービス管理下ならその停止操作を使います。Windowsでは minihub.exe stop -config minihub.json -wait 60s を使えます。
  2. データディレクトリ全体と設定ファイルを、データディレクトリの外へバックアップします。

Windowsの停止・ZIPバックアップは 管理者マニュアルの手順を参照してください。

復元

復元時もサービスを停止し、既存データと混ぜずに整合したバックアップ全体を戻します。設定の server.dataDir を確認してから起動し、ログインと履歴を確認します。

投稿の物理削除は 削除手順に従って停止中に実行します。

実装の詳細はリポジトリの DESIGN.md、検証方法は tests/README.md を参照してください。
