# ブックマーク機能の検討資料

> **未実装の検討資料です。現行仕様ではありません。** 実装する際は、着手時点のコードと照合してください。本文の行番号・関数名・スキーマ版数は作成時点の実装に基づきます。

## 背景

投稿・返信のうち「確認中のもの」「後で確認したいもの」を管理したいという要望があります。問題は目印を付けられないことより、**付けた投稿を後から一覧で見つけられないこと**にあります。現在は「確認中」リアクションで目印は付けられますが、自分が付けた投稿の一覧がなく、チャンネルをさかのぼって探すしかありません。

## 結論：リアクションとは別の「自分専用ブックマーク」を追加する

| 観点 | 確認中リアクションを流用 | 自分専用ブックマーク（推奨） |
| --- | --- | --- |
| 見え方 | 全員に見え、押した人も分かる | 本人だけ。「後で読む」を周囲に見せずに済む |
| 意味 | 「対応中」という周囲への合図 | 自分の作業リスト。目的が別なので両立できる |
| 片付け | 外すと周囲への合図も消える | 解除しても周囲に影響しない |
| 利用条件 | 参加者のみ（`canPost`） | 閲覧できれば可（`canRead`）。未参加の公開チャンネルも可 |
| サーバー負荷 | 変更のたびに全員へWebSocket配信 | **WebSocket配信なし**。増えるのはHTTPのみ |
| 実装 | 表は流用できるが、ユーザー起点の索引と一覧APIは結局必要 | 小さな新規テーブル1つ |

「確認中」リアクションは今のまま残します。**周囲に伝えるのはリアクション、自分用の管理はブックマーク**と使い分けます。両者は連動させません（⏳を押しても自動でブックマークされません）。連動させると「⏳を外すと消えるのか」「✅で消すのか」という曖昧さが生まれるためです。

## ユーザー体験

1. **付ける**：投稿・返信の操作行（リアクション＋の並び）にしおりアイコンを追加します。ホバー時に表示し、押すと塗りつぶしになります。付いている投稿では常時表示します。タッチ端末では既存どおり常時表示です。ほかの表現方法との比較は「[付いた状態の表現](#付いた状態の表現)」を参照してください。
2. **一覧を見る**：左サイドバーの「関連機能」（AIキャンバス、予定調整一覧の並び）に「ブックマーク（件数）」を追加します。押すと右からパネルが開き、追加が新しい順に、チャンネル名・投稿者・本文抜粋・投稿日時を表示します。件数は灰色の控えめな表示とし、未読のような赤バッジにはしません。
3. **戻る**：行を押すと該当の投稿へ移動してハイライトします。返信ならスレッドを開きます。移動しただけでは解除しません。
4. **片付ける**：確認が終わったら一覧の行の「解除」か、投稿のしおりを再度押します。ブックマークは1状態のみで、解除が「確認済み」を兼ねます。

上部ヘッダーはアイコンが既に多いため増やしません。通知センターのタブにも入れません（通知とは性質が違い、タブ切替処理が `app.js` と `threads.js` に分散しているため）。サイドバーのリンクから専用のオフキャンバスを開きます。

### 付いた状態の表現

ブックマーク済みの投稿をタイムライン上でどう見せるかには、複数の案があります。主な確認手段は一覧なので、タイムラインでは「付いていることが分かる」程度で足り、会話を読む妨げにならないことを優先します。

| 案 | 見え方 | 利点 | 懸念 | 評価 |
| --- | --- | --- | --- | --- |
| A. 操作行のアイコンを塗りつぶす | リアクションの並びに、塗りつぶしたしおりを常時表示 | 操作と状態が同じ場所で、もう一度押せば解除できる。追加要素が最小で、返信にも同じ部品で付く | 共有されるリアクションと並ぶため、他の人にも見えると誤解されやすい。投稿の下端にあるので、長い投稿では目に入りにくい | **初期実装に推奨** |
| B. カード右上にマーク | 投稿の右上に小さなしおりを固定表示 | 位置が一定で、スクロール中に見つけやすい。リアクションの増減で動かず、自分用の印として区別しやすい | 連続投稿は見出し行がなく本文が1行目から始まるため、狭い画面で本文と重ならない余白が要る。操作行と別に要素が増える | **次の候補** |
| C. カード左上にマーク | 投稿の左上に小さなしおりを固定表示 | 視線の起点にあり最も目立つ。本のしおりの印象に近い | 左上は投稿者名や本文の開始位置で、重ねるか全投稿の字下げが必要。左端の帯（`mine`、`mentioned`）とも近接する | 非推奨 |
| D. 見出し行に表示 | 投稿者名・時刻の並びに「自分」ラベルのような印を追加 | 既存の表示規則に沿い、レイアウトへの影響が小さい | 連続投稿は `.message.continued .head` で見出し行が非表示のため、印も消える。別の置き場所が必要になる | 非推奨 |
| E. カードの背景色を変える | 投稿全体を薄く着色 | 一覧性が最も高い | 背景色は既に `mine`（灰）、`mentioned`（黄）、`notification-target`（濃い黄）で使用中で、意味が衝突する。重なった場合の優先順位も増える。多用するとタイムラインが騒がしくなる | 非推奨 |
| F. 左端の帯を変える | 投稿左端の縦線に色を付ける | 控えめで、長い投稿でも分かる | E と同じく `mine`、`mentioned` が使用中。色だけでは意味が伝わらない | 非推奨 |

**推奨**：初期実装はAとします。操作と状態が一か所にまとまり、ブックマークの実装案（`reactionBar()` 内に置く）とも整合します。誤解への対策として、リアクションのチップ型にはせず件数も出さない別の見た目にし、ツールチップを「ブックマーク（自分にだけ表示）」とします。運用で「付いている投稿を見つけにくい」「他の人に見えると思った」という声が出たら、Bを状態表示として追加します。

どの案でも次を満たします。

- 色だけに頼らず、アイコンの形（枠線と塗りつぶし）でも区別します。
- ボタンには `aria-pressed` と「ブックマークに追加」「ブックマークを解除」の `aria-label` を付けます。
- タッチ端末でも押しやすい操作領域を確保します。

Aには次の制約があります。いずれもBを追加すれば状態を表示できます。

- 取り消し済みの投稿には `reactionBar()` が描画されないため、タイムラインに状態が出ません。解除は一覧から行います。
- スレッドパネルの親投稿にも `reactionBar()` がないため、パネル内では状態が出ません。

### 境界条件

- **取り消された投稿**：一覧に残し「取り消されました」と表示します。本文は返しません（`publicMessage` を通す）。解除でき、取り消しが戻れば本文も戻ります。取り消し済みの投稿には新規に付けられません。
- **閲覧権限を失った場合**（非公開チャンネルからの除外、アーカイブ）：一覧に出しません。行は保持し、権限が戻れば再表示します。
- **保存期間による物理削除**：ブックマークは削除を止めません。投稿と一緒にブックマークも消えます。ユーザーマニュアルに明記します。
- **件数上限**：1人500件です。超過時は解除を促すメッセージを返します。一覧が際限なく増えて放置されるのを防ぎ、一覧処理の上限も固定します。非表示の行も件数に含みます。
- **別タブ・別端末**：WebSocket配信しないため、しおりの状態はチャンネルを開き直すか再接続した時点で揃います。PUT／DELETEは冪等なので、ずれていても害はありません。

### 初期範囲に入れないもの

メモ、期限・リマインド、フォルダ・タグ、ステータス分類（確認中／後で）、他者との共有、既存の⏳リアクションからの移行。実運用で要望が出てから検討します。

## 実装案

### 1. 保存（スキーマ v8 → v9）

[store.go](../internal/storage/sqlitestore/store.go)

```sql
CREATE TABLE bookmarks(
  id INTEGER PRIMARY KEY,
  user_id TEXT NOT NULL, channel_id TEXT NOT NULL, seq INTEGER NOT NULL CHECK(seq>0),
  created_at TEXT NOT NULL,
  UNIQUE(user_id,channel_id,seq));
CREATE INDEX bookmarks_user ON bookmarks(user_id,id);
```

- `schema` 定数と `version >= 1 && version <= 8` の移行ブロックの両方に追加します。`Open` のバージョン上限と [inspect.go](../internal/storage/sqlitestore/inspect.go) の上限、`webhooks_test.go` の期待値も9に更新します。
- `id` は並び順とカーソルを兼ねます。`id < cursor` で引くので、ページング中に解除してもカーソルは無効になりません。
- `(channel_id, seq)` は再利用されないため、別の投稿を指すことはありません。
- 個人の現在状態なのでイベント履歴は持ちません（`read_state` と同じ扱い）。
- [retention.go](../internal/storage/sqlitestore/retention.go) の削除リストに、`messages` 削除より前の位置で `bookmarks` を追加します。

Storage契約（[storage.go](../internal/storage/storage.go)、実装は `sqlitestore/bookmarks.go` を新設）：

- `AddBookmark(ctx, user, channel, seq, limit, at) error`：同一トランザクションで件数確認と `INSERT OR IGNORE` を行います。超過時は `storage.ErrBookmarkLimit` を返します。
- `RemoveBookmark(ctx, user, channel, seq) error`
- `ListBookmarks(ctx, user) ([]domain.Bookmark, error)`：`messages` と結合し `id DESC` で返します（最大500件）。`scanMessage`／`messageColumns` を再利用します。
- `BookmarkedSeqs(ctx, user, channel) ([]int64, error)`

`domain.Bookmark` は [models.go](../internal/domain/models.go) に追加します（`ID`、`ChannelID`、`Message`、`CreatedAt`）。

### 2. Service（`internal/service/bookmark.go` を新設）

- `AddBookmark`：`canRead` → `GetMessage` → `messageWithdrawal` の順で確認します。`SetReaction` の確認手順にならいますが、権限は `canPost` ではなく `canRead` です。
- `RemoveBookmark`：本人の行のみが対象で、ID検証のうえ `canRead` を要求しません。権限を失っても自分の行は消せるようにします。
- `ListBookmarks`：`ListChannels` で読めるチャンネルに絞り込み（`ListMentions` と同じ方式）、ページ分だけ `publicMessage` で取り消しを反映します。`limit` の扱いも `ListMentions` と同じです（既定50、最大100）。応答は `{bookmarks, total, nextCursor}` です。
- `BookmarkedSeqs`：`canRead` のうえ返します。

### 3. API

[httpapi.go](../internal/httpapi/httpapi.go) の `reactions` のルートと同じ場所に追加します。

| メソッド | パス | 用途 |
| --- | --- | --- |
| `GET` | `/api/bookmarks?limit=50&cursor=` | 自分の一覧 |
| `GET` | `/api/channels/{id}/bookmarks` | そのチャンネルで自分が付けた `seq` の配列 |
| `PUT` | `/api/channels/{id}/messages/{seq}/bookmark` | 追加（冪等、204） |
| `DELETE` | `/api/channels/{id}/messages/{seq}/bookmark` | 解除（冪等、204） |

ユーザーIDはセッションからのみ取得し、他人のブックマークを参照する手段は作りません。

### 4. Web UI

- [app.js](../web/js/app.js)
  - `S.bookmarks`（現在のチャンネルの `seq` の Set）を追加し、`select()` の `syncReactions` の隣とWebSocket再接続時に同期します。取得失敗でチャンネル表示を止めません。
  - `reactionBar()` の末尾でしおりボタンを生成します。bar内に置くと、`refreshThreadReaction` の再生成でも状態が保たれ、返信にも自動で付きます。スレッドパネルの親投稿にはbarがないため、親投稿は本流のタイムラインから操作します。
  - 押下時はそのボタンだけ更新します（`render()` を呼びません）。
  - `openMention` の移動処理を `jumpToMessage(channelId, message)` に切り出して共用します。切り出しの際、`around` で読み込んだ後に `syncReactions` を呼ぶようにします。現行の `openMention` はこの同期を行っていないため、古い投稿へ移動するとリアクションが表示されません。
- 新規 `web/js/bookmarks.js`：パネルの読み込み・描画・解除・さらに読み込むを担当します。行は「移動ボタン＋解除ボタン」の構成にします（ボタンの入れ子を避けるため）。文字列は `textContent` のみで表示し、本文表示に `messageDisplayText` を使います。ログイン時と再接続時に件数を取得します。
- [index.html](../web/index.html)：サイドバーのリンク、`#bookmarkPanel` オフキャンバス、ヘルプの節を追加します。アイコンは同梱済みの `bookmark`／`bookmark-fill` を使います。
- CSS：[threads.css](../web/css/threads.css) の `@media (hover: hover)` の非表示ルールに、未ブックマークのボタンを追加します。

## 運用上の注意

スキーマv9は一方向で、起動すると旧バージョンのバイナリではDBを開けなくなります（`unsupported SQLite schema version`）。展開前に `minihub backup` を取得してください。切り戻しはバックアップからの復元になり、それ以降の投稿は失われます。

## 検証項目

- **Storage**：追加・解除の冪等性、500件上限、新しい順、解除後もカーソルが有効、再起動後の保持、v8からの移行（`webhooks_test.go` の移行テストと同型）、バックアップからの復元。
- **保存期間**（`backend/retention_test.go`）：投稿と親削除に伴う返信のブックマークが消える、dry-runでは残る、`seq` が再利用されない。
- **Service／API**：非参加の非公開チャンネルは404、除外後は非表示で再参加で復帰、アーカイブ中は非表示、未参加の公開チャンネルは可、他ユーザーから見えない、取り消しで本文が消え復元で戻る、取り消し済みへの追加拒否、ルートと入力検証。
- **ブラウザ**：`tests/bookmarks-browser.mjs` を新設します。投稿と返信への追加、最新100件より古い投稿への移動とハイライト、移動先のリアクション表示、一覧からの解除、ページング、スマートフォン幅で操作行がはみ出さないことを確認します。既存の `tests/threads-browser.mjs` も実行します。
- **実行**：`go test ./...`、`go vet ./...`、`go test -race ./...`
